# جهت معماری بازسازی

## ساختار پیشنهادی

```text
apps/
  game/       وب‌اپ بازی فارسی و پوستهٔ Capacitor
  admin/      پنل مدیریتی مستقل
  api/        بک‌اند مشترک
packages/
  contracts/  قراردادها و مدل‌های مشترک API
  ui/         اجزای اشتراکی در صورت نیاز
docs/
  product/    تصمیم‌ها و قواعد محصول
```

## فناوری پیشنهادی

- بازی و پنل: Angular با standalone components و RTL-first design.
- موبایل: Capacitor روی `apps/game`، نه یک اپ جداگانه.
- API: NestJS با REST برای عملیات عادی و Socket.IO برای 1v1 و اعلان‌های realtime.
- داده: PostgreSQL و Prisma.
- زمان: همهٔ deadlineهای بازی روی سرور ثبت و محاسبه می‌شوند؛ clock مرورگر صرفاً نمایشی است.

## اصول امنیت و یکپارچگی

- پاسخ صحیح سؤال هرگز پیش از ثبت پاسخ به کلاینت فرستاده نمی‌شود.
- هر session بازی شامل شناسهٔ سؤال‌ها، deadline سمت سرور و وضعیت هر پاسخ است.
- پاسخ تکراری، پاسخ خارج از session و پاسخ بعد از deadline رد می‌شود.
- سکه و امتیاز با تراکنش دیتابیس و دفتر تغییرات ثبت می‌شوند.
- پرداخت و پکیج سکه فقط با شناسهٔ پکیج سمت سرور انجام می‌شود؛ کلاینت نمی‌تواند مقدار پول یا سکه تعیین کند.
- WebSocket با JWT احراز هویت می‌شود و دسترسی به هر اتاق مسابقه کنترل می‌شود.

## مرزهای MVP

MVP شامل تک‌نفرهٔ آنلاین، 1v1 تصادفی، OTP، پروفایل عمومی، رتبه‌بندی ماهانه، مأموریت و streak، مدیریت محتوا، گزارش و پشتیبانی است.

فازهای بعد شامل لابی گروهی، دوستی و دعوت مستقیم، push notification موبایل، آپلود آواتار، پرداخت واقعی و پیشنهاد سؤال بازیکن است. مدل و workflow پیشنهاد سؤال از ابتدا در طراحی لحاظ می‌شود.
